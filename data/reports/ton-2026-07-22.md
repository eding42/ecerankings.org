## Needs human review

**Harvesting note for whoever runs step 6 (orchestrator/user) — read before
harvesting this venue:** TON now has *two* `openalex_ids`
(`S62238642`, `S5407042750`) with disjoint year coverage that splits mid-2024.
Checked `pipeline/harvest.py`'s `resolve_year_sources()` directly: if this
venue gets a `years{}` registry entry that pins year 2024 to a single `id`
(the pattern used by e.g. TPWRS/TSG), `harvest.py` will use *only* that one
source for 2024 and silently drop the other source's ~60 or ~219 papers. The
safe path — and what this registration deliberately uses — is to register
**both IDs in `openalex_ids` and add no `years{}` entry at all**. With no
per-year entry, `resolve_year_sources()` falls to its "filtered" branch, which
ORs *every* ID in `openalex_ids` together (`source_filter = "|".join(...)`)
plus a `publication_year` filter — exactly the union behavior every year
needs, since each source only has works in its own real coverage window (no
overlap, confirmed above). Concretely: run
`python3 pipeline/harvest.py --venue ton --year-range 2017 2026` (not
`--all-years`, which requires a populated `years{}` and will refuse to run
with none registered).

Beyond that harvesting caveat, nothing is left unresolved for this venue
within the 2017–2026 window — the mid-2024 ISSN/source split itself was
fully resolved: both source IDs identified, verified, and cross-checked for
non-overlap, each independently passing every checklist item.

One item worth flagging for awareness (not blocking `verified`): the new
source's OpenAlex `display_name` is "IEEE Transactions on Networking"
(no "/ACM") and its `host_organization_name` is null. These are cosmetic
OpenAlex metadata gaps on a newly-created source record, not signals of a
real rename or co-sponsorship change — corroborated by IEEE Xplore, ACM
Digital Library, and IEEE ComSoc all still branding the journal
"IEEE/ACM Transactions on Networking" as of Volume 33 (2025). No action
needed, but if a future OpenAlex data refresh changes this source's fields,
it's worth a quick re-check.
