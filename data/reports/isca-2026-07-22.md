# Collection report: isca (architecture) — 2026-07-22

## Summary

Window applied: **2017–2026**, per explicit orchestrator instruction (not the
skill's default last-10-years window, which would have been 2016–2025 — note
this so 2016 is understood as out of scope, not overlooked).

ISCA has **no comprehensive per-year (or generic series) OpenAlex source at
all** — worse fragmentation than the "per-year source exists, just lags"
pattern seen on IEDM/ISSCC/DAC. Every `/sources` search variant ("International
Symposium on Computer Architecture", "Annual International Symposium on
Computer Architecture", "ISCA") returns either unrelated lookalikes or a
single sparse historical catch-all (`S4306420111`, 128 works scattered
1976–2019, 1–16/year, no useful in-window coverage). All 9 in-window published
years (2017–2025) were instead resolved via Crossref, verified by DOI prefix
(not raw hit count — the fuzzy `query.container-title` search returns
hundreds of thousands of irrelevant hits per year; every year's results were
filtered to titles containing "International Symposium on Computer
Architecture" while excluding HPCA/SBAC-PAD/CADS/workshop lookalikes, then
cross-checked against DBLP's per-year edition list, which matched exactly).
2026 (the 53rd edition) **was held** June 27–July 1, 2026, but its proceedings
are not yet registered in Crossref or OpenAlex as of this report (~3 weeks
post-conference) — a pending-publication gap, not a real absence.

Confirmed (contrary to the initial assumption) that ISCA does **not** cleanly
alternate ACM/IEEE every year: the alternation broke twice in this window —
2020 and 2021 were both IEEE-hosted (pandemic-era virtual/Valencia editions),
and 2022 and 2023 were both ACM-hosted. DOI-prefix format for IEEE years is
also inconsistent across editions: 2018 uses a dotted `isca.2018.NNNNN` form
with no conference-id, while 2020/2021/2024 use a conference-id-bearing
`isca<confid>.<year>.NNNNN` form matching that year's front-matter DOI.

A genuinely useful and unexpected finding: spot-checking OpenAlex's own copies
of these Crossref-originated, source-less ("orphaned") ISCA works shows **~98%
authorship→institution resolution** (45/46 sampled authorships across ACM and
IEEE years alike) — see "Needs human review" for why this doesn't change the
registration approach but is worth flagging for the harvest step.

Overall confidence: **high** for venue identity and per-year counts (DOI-prefix
verified, cross-checked against DBLP); **appropriately incomplete** for 2026
(not yet published anywhere) and for a formal affiliation-coverage
number (no dedicated OpenAlex source exists to run the checklist's item 4
against, though the spot-check above is a strong informal substitute).

## Needs human review

1. **2026 status is a judgment call, flag for orchestrator consistency.**
   Per the skill's "what verified means" bar, a held-but-not-yet-indexed year
   is expected lag, not a blocking gap — so `status: "verified"` is
   defensible. But this is the one contestable point in this report, and the
   sibling architecture-area workers (MICRO/HPCA/ASPLOS, run in parallel,
   invisible to this worker) are very likely hitting the exact same "2026 not
   yet published" wall. Recommend the orchestrator apply the same 2026-gap
   treatment across all four venues for consistency rather than each worker
   deciding independently.
2. **Orphaned OpenAlex records for ISCA carry resolved institutions ~98% of
   the time** (spot-checked 46 authorships across both ACM- and IEEE-hosted
   years, 45/46 resolved) — noticeably higher and more consistent than the
   IEDM-sweep finding in `PLAN.md` Phase 1b ("institution resolution on
   orphaned records was inconsistent... not reliable enough to build a
   special path around"), which is why that path was rejected there. This
   sample is small (not a full ~25-per-venue systematic sweep) and doesn't
   change ISCA's registration here — `years{}` still correctly points at
   Crossref as the source of record — but it may be worth a larger
   systematic check before/during Phase 1b harvesting: if it holds up at
   scale, `pipeline/harvest_crossref.py` (or a variant) could potentially
   pull already-resolved institutions straight from OpenAlex's `/works?
   filter=doi:...` batch lookup for these DOIs instead of relying on
   `normalize_affiliations.py` to parse Crossref's free-text affiliation
   strings — a possible efficiency win, not a methodology change, and not
   something this worker is scoped to decide. Flagging for whoever runs the
   ISCA harvest.
3. **DOI-prefix format instability confirmed** (dotted `isca.2018.NNNNN` vs.
   conference-id-bearing `isca45697.2020.NNNNN`) — already anticipated by
   `PLAN.md`'s "DOI prefixes are NOT constant across years" note, but this is
   a second axis of variation (format, not just the numeric ID) worth keeping
   in mind if `harvest_crossref.py`'s DOI-prefix validator does any prefix
   pattern-matching rather than exact per-year string comparison.
4. Rejected lookalikes, for the record: `S4210184388` ("Proceedings -
   International Symposium on High-Performance Computer Architecture/
   Proceedings") is HPCA, not ISCA, despite a near-identical display name —
   classic lookalike trap. `S4210215238` ("Proceedings", generic, IEEE) too
   vague/unverifiable to be ISCA-specific. `S4393916863` ("Proceedings -
   International Symposium on Computer Architecture/Proceedings") has
   `works_count: 0` — right name, no content, not usable.

No other ambiguities. Harvesting was not performed (steps 1–5 only, per this
skill's scope for worker mode) — that decision is the top-level agent's to
make with the user, not this worker's.
