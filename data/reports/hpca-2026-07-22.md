## Year-coverage gaps
None within 2016–2026. Every edition has a Crossref-covered, DOI-prefix-validated
count (2016–2025 as already registered; 2026 newly added this pass). No native
OpenAlex per-year source exists for any of these years — confirmed via
`/sources` search across multiple name variants ("HPCA", "IEEE HPCA",
"International Symposium on High Performance Computer Architecture",
`display_name.search`): the only close-name hit is `S4210184388`
("Proceedings - International Symposium on High-Performance Computer
Architecture/Proceedings"), which is 100% 2008 papers (33 works) — a legacy
source from an era before OpenAlex's conference fragmentation pattern took
hold, and outside any year we need. This is the same "no per-year source
exists, Crossref covers every year" pattern already documented in the
registry notes; this pass just confirms it still holds and extends it one
more year.

**2026 edition confirmed**: `10.1109/hpca68181.2026`, ~121–122 real papers
(1 "Message from General Chair" entry identified and excluded from the raw
122 DOI-prefix matches found via paginated Crossref search, stabilized after
500+ rows with zero new matches in the next 1,000). Note: Crossref's
`query.container-title` fuzzy search can under-surface low-relevance-scored
entries (pure front-matter like "Title Page"/"Copyright" often don't rank
highly enough to appear even after 1,500 rows — this was also true when
re-checking 2025's already-registered count from scratch, where my
from-scratch retrieval undercounted vs. the registered 122). This is a known
limitation of the container-title endpoint (per SKILL.md: "don't trust the
result count, verify by DOI prefix"), not evidence the registered/new counts
are wrong — the 2022 exact-match spot-check gives good confidence the
existing methodology is sound. Recommend accepting 2026's count as
provisional (~121) and letting `harvest_crossref.py`'s exhaustive cursor-paged
DOI-verified pull (Phase 1b) produce the authoritative final count when that
year is actually harvested.
